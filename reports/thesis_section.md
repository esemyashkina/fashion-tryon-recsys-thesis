# Оценка качества рекомендательного модуля

## 3.1 Подготовка данных

Эксперимент проверяет, насколько точно рекомендательный модуль подбирает замену одному предмету одежды по фотографии образа. В запросе задаётся категория вещи. Тип, цвет и стиль можно указать дополнительно. Для каждого запроса формируется список всех товаров соответствующего каталога, удовлетворяющих заданным условиям.

Сценарии формировались на основе парных сравнений. При автоматической генерации подготавливались два образа и две карточки одежды с одинаковыми значениями основных фильтров. Карточки различались по видимому признаку, например силуэту, рисунку или декоративной детали. План строился так, чтобы первая вещь лучше подходила первому образу, а вторая – второму. Для планов и описаний применялась GPT-6.1 Terra, для генерации изображений в автоматических сериях – GPT Image 2.6 Sunburst. Сценарии проходили предварительную автоматическую проверку визуальной различимости вариантов и соответствия замыслу.

Скрипт prepare_catalog_benchmark.py формировал запросы к полному каталогу на основе парных сценариев. Для дополнительных запросов перебирались варианты снятия ограничений по типу вещи, цвету и стилю. Категория сохранялась. Запрос добавлялся, если снятие фильтра расширяло список товаров и такой набор условий для данного фото ещё не встречался. При разметке полного списка вручную отмечались все подходящие карточки. Сочетаемость оценивалась по одежде, обуви и аксессуарам, которые остаются после замены.

Состав итоговой версии приведён в таблице 3.1. При подборе дополнительных валидационных запросов учитывались число заданных фильтров и размер списка кандидатов. Связанные фотографии, карточки и сценарии одного пакета относились к одной выборке. После разделения скрипт проверял отсутствие общих файлов изображений по контрольным суммам. Доля неполных запросов составила 56,1 % в обеих выборках. Для дополнительного диагностического сравнения из валидационной выборки исключены пять запросов с повторяющимися ошибками прототипа в двух прогонах. Тестовая выборка сохранила все 57 запросов.

## 3.2 Алгоритм и метрики

После применения фильтров GPT-6.1 Terra формирует текстовое описание желаемой вещи по фотографии. FashionCLIP кодирует описание и фотографии товаров в общее векторное пространство. Карточки ранжируются по косинусной близости. Первые K карточек вместе с исходной фотографией и запросом передаются GPT-6.1 Terra для финального выбора. Если найдено меньше K товаров, передаются все найденные карточки. Используются предварительно обученные модели с зафиксированными весами. На валидационной выборке подбираются размер списка K и промпт финального выбора. Критерием подбора служит точность первого выбора. В эксперименте для Terra использовался режим рассуждения medium.

Запрос считается обработанным успешно, если выбранный товар входит в множество отмеченных подходящих карточек. Precision@1 равна доле успешных запросов. Hit@K равна доле запросов, для которых среди первых K товаров есть хотя бы один подходящий. В качестве базового уровня вычисляется ожидаемая точность равновероятного выбора после фильтрации. Для каждого запроса она равна отношению числа подходящих карточек к числу кандидатов.

## 3.3 Настройка и результаты

На диагностической выборке по сохранённым предсказаниям сравнивались K = 2, 4 и 6 при исходном промпте Visual Conflicts v3. Текстовый запрос по фото был общим для трёх значений K. При равенстве Precision@1 выбирался меньший список. Результаты приведены в таблице 3.2.

Таблица 3.2 – Выбор числа карточек на валидации
| K | Hit@K | Precision@1 |
|---:|---:|---:|
| 2 | 107/114 (93,9 %) | 95/114 (83,3 %) |
| 4 | 114/114 (100,0 %) | 96/114 (84,2 %) |
| 6 | 114/114 (100,0 %) | 99/114 (86,8 %) |

При выбранном K сравнивались три промпта на одинаковых карточках в одном порядке. Visual Conflicts v3 предлагает искать конкретные визуальные конфликты. «Готовые образы» предлагает сравнить итоговый образ для каждого кандидата. «Подробные стилевые правила» задаёт критерии по палитре, пропорциям, фактурам и характеру деталей. На тесте приведены результаты сохранённого прогона конфигурации с наибольшим Precision@1 на валидации. При равенстве предпочтение отдавалось базовому промпту, затем «Готовым образам».

Для итогового прогона зафиксированы K = 6 и промпт «Готовые образы». Его точность на сокращённой валидации составила 93,0 %. Тестовые сценарии использовались на предшествующих этапах разработки. В итоговом прогоне на них оценена одна конфигурация, выбранная по валидации. Сравнение методов приведено в таблице 3.4.

На тесте подходящая карточка занимала первое место в 26 запросах при поиске по тексту фильтров и в 36 запросах при поиске по описанию образа. Полный прототип выбрал подходящую вещь в 52 из 57 запросов (91,2 %). Во всех 57 запросах среди переданных на финальный выбор карточек была хотя бы одна подходящая.
